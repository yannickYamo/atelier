## Summary

This change adds digest assembly helpers for the daily mail job: message truncation, timestamp formatting, thread grouping, and per-thread rendering. `build_digest` stitches the pieces into a plain-text body for a single recipient, with an early return for the empty case.

## Must fix

- **src/mail/digest.py:65** — The loop `range(len(messages) - 1)` stops one short, so the most recent message in every thread is silently dropped from the bullet list. The header on line 60 still reports the full count, so the output contradicts itself. Use `for msg in messages:`.
- **src/mail/digest.py:67** — `msg["received_at"]` is indexed directly while every other field uses `.get()` with a fallback, so one message missing a timestamp raises `KeyError` and kills the whole digest. Supply a default or skip the bullet.
- **src/mail/digest.py:43** — `datetime.datetime.utcfromtimestamp` is deprecated from Python 3.12 and emits a `DeprecationWarning`. Use `datetime.datetime.fromtimestamp(ts, datetime.timezone.utc)`.

## Suggestions

- No tests accompany this change. Add a test for `render_thread` asserting that a three-message thread produces three bullets — that single case would have caught the line 65 defect — plus a test for `build_digest` with an empty message list.
- `_truncate` on line 37 slices to `limit - 1` and appends an ellipsis, which yields a string of `limit` characters; that is probably intended, but a brief comment would save the next reader from re-deriving it.
- `render_thread` on line 58 assumes `messages` is non-empty. It is only reached via `group_by_thread`, which guarantees that today, but an explicit guard would make the function safe to call directly.
