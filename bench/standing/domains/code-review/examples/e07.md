## Summary

This change adds a Redis-backed cache layer for user profiles and avatars, with namespaced keys, a five-minute TTL, and an `invalidate` helper that clears both entries. Lookups fall back to the database on a miss and refill the cache. Corrupted JSON is tolerated and treated as a miss.

## Must fix

- **src/profile/cache.js:87** — The profile key omits `userId`, so every user with the same locale shares one cache entry. The first request to populate `profile:v2:en-US` causes that profile to be served to every other user, a cross-account data leak. Interpolate `userId` into the key.
- **src/profile/cache.js:136** — When `findByUserId` returns no avatar, `JSON.stringify(undefined)` yields `undefined`, which is written to Redis and later parsed back as a miss. Return early on a falsy `avatar` instead of caching it, as `getProfile` does at line 119.
- **src/profile/cache.js:141** — `invalidate` only deletes the key for the default locale, leaving stale profiles behind for every other locale a user has visited. Track written locales or use a per-user key prefix that can be dropped in one operation.

## Suggestions

- Add a test asserting that `getProfile` for two distinct user ids at the same locale returns two distinct profiles; this is the regression that line 87 introduces and the one most likely to recur.
- Add a test covering `invalidate` across more than one locale.
- Consider logging in the `catch` at line 104. Silently swallowing a parse failure hides persistent corruption, since the entry is rewritten on every miss and the problem never surfaces.
