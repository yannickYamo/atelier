## Summary

This change adds a small statistics module providing `total`, `mean`, `trimmed_mean`, `weighted_mean`, `variance` and a `summarise` convenience wrapper over numeric samples. Each helper coerces its input to a concrete list of floats via `_coerce`. Most functions guard against empty input, but the trimming path does not.

## Must fix

- **src/stats/average.py:165** — `len(samples)` can be zero here, raising `ZeroDivisionError`. Any sample with `len(values) <= 2 * trim` (including an empty sample) trims to nothing; return `0.0` or raise a clear `ValueError` instead.
- **src/stats/average.py:164** — A negative `trim` silently produces `samples[-n:len-(-n)]`, which yields a wrong or empty slice rather than an error. Validate that `trim >= 0` before slicing.
- **src/stats/average.py:194** — `len(values)` assumes a sized sequence, while the sibling calls accept any iterable; passing a generator raises `TypeError` and also exhausts the input before `total` sees it. Coerce once at the top of `summarise` and reuse the list.

## Suggestions

- `total` reimplements a loop that `sum(_coerce(values))` already expresses; the explicit accumulator adds nothing.
- `variance` returns `0.0` for a one-element sample, which is defensible, but the docstring should say so since callers cannot distinguish it from a genuinely flat sample.
- No tests accompany this module. Add unit tests for `trimmed_mean` covering the degenerate cases — empty input, `len(values) == 2 * trim`, and `len(values) < 2 * trim` — plus a `weighted_mean` case with zero total weight.
