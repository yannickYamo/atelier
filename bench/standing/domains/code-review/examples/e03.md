## Summary

This change adds a session token module that mints opaque tokens, stores only their SHA-256 digests, and rotates a token once it passes a fifteen-minute window. `issue()` creates a handle/token pair and persists the record; `rotate()` verifies the presented token against the stored digest and, when stale, removes the old record and issues a replacement.

## Must fix

1. **src/tokens/rotate.js:47** — The session token is generated with `Math.random()`, which is not cryptographically secure and is predictable from observed outputs; an attacker who sees a few tokens can forge others. Use `crypto.randomBytes(TOKEN_BYTES).toString('hex')`, which also makes the declared `TOKEN_BYTES` constant meaningful instead of unused.
2. **src/tokens/rotate.js:95** — Comparing digests with `!==` is a non-constant-time comparison and leaks match position through timing. Compare with `crypto.timingSafeEqual` over equal-length buffers.
3. **src/tokens/rotate.js:102** — The old record is removed before the new one is issued, so a failure in `issue()` destroys a valid session with no replacement. Issue first, then remove, or wrap both in a single store transaction.

## Suggestions

1. `rotate()` returns the presented token unchanged when the record is fresh, so callers cannot distinguish "verified, still valid" from "newly rotated" without reading `rotated`. Consider documenting that contract in the JSDoc above `rotate()`.
2. No tests accompany this module. Add unit tests covering: rotation at the stale boundary (`now - issuedAt === MAX_AGE_MS`), a mismatched `presented` token returning `null`, and an unknown handle returning `null`.
3. `isStale()` treats a missing or non-numeric `issuedAt` as stale, which is safe but silent; logging that case would help diagnose corrupted records.
