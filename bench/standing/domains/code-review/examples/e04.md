## Summary

This change adds CSV import helpers: `read_records` opens a file, validates the header against a required column set, normalizes each row, and converts the amount field into cents. `import_file` wraps that to push every parsed record into a caller-supplied sink and returns the count. The module also defines a custom `ImportError_` exception for parse failures.

## Must fix

- **src/import/csv.py:87** — The `raise` re-raises the header error while `handle` is still open, leaking the file descriptor on the error path. Use `with open(...) as handle:` (or a `try/finally`) so the file is closed on every exit.
- **src/import/csv.py:96** — Because the close is only reached on the success path, any exception raised inside the row loop leaks the handle too. The same `with` block fixes both cases.
- **src/import/csv.py:92** — `parse_amount` will raise a bare `ValueError` on malformed input, and `record["amount"]` raises `KeyError` on a short row; neither is wrapped in `ImportError_`, so callers can't catch import failures uniformly.

## Suggestions

- The module is named `csv.py` and does `import csv`; this works under absolute imports but is confusing, and shadows the stdlib name for anyone reading the package. Consider `csv_import.py`.
- `ImportError_` with a trailing underscore is awkward. `CSVImportError` reads better and avoids any confusion with the builtin.
- No tests accompany this behaviour. Add tests for `parse_amount` (`"$1,234.50"` → `123450`, empty string → `0`, malformed input), and a `read_records` test asserting the handle is closed after a missing-column header raises.
