## Summary

This change adds a ZIP export module that walks a directory tree, assembles a staging archive on disk, and streams it to a caller-supplied destination. It stages under `EXPORT_SPOOL_DIR` (defaulting to `/tmp`) so large reports are not held in memory, and optionally removes the staging file afterwards.

## Must fix

- **src/export/zip.py:128** — The staging file name is fully predictable (`export-<job_id>.zip`) in a world-writable directory. An attacker who can guess or observe `job_id` can pre-create the path or a symlink and cause the export to clobber or disclose another file. Use `tempfile.mkstemp`/`NamedTemporaryFile` with a private-mode directory, or open with `O_CREAT | O_EXCL`.
- **src/export/zip.py:176** — `shutil.rmtree` only removes directories; on a file it fails, and `ignore_errors=True` swallows the error. The staging archive is never deleted, so `/tmp` fills over time. Use `os.unlink` (or `Path.unlink(missing_ok=True)`).
- **src/export/zip.py:155** — `archive.write` follows symlinks and `_arcname` does not guard against paths escaping `root`, so a symlink under `root` can pull arbitrary file contents into the archive. Skip symlinks in `collect_files` or resolve and verify each path stays within `root`.

## Suggestions

- `export` returns `archive_path` after the file has been deleted, which is misleading; return nothing, or return the path only when `cleanup=False`.
- `job_id` is interpolated directly into a filename; reject or sanitise values containing path separators even after the tempfile fix.
- No tests accompany this module. Add tests for `collect_files` hidden-file filtering and ordering, for `export` removing its staging file, and for a symlink under `root` not being archived.
