## Summary

This change adds an outbound webhook delivery module that serialises an event, signs it with HMAC-SHA256 using the subscriber's shared secret, and POSTs it over HTTPS. Delivery is retried up to three times, treating any status below 500 as final. The module exports `signPayload`, `buildRequestOptions` and `deliver`.

## Must fix

- **src/notify/webhook.js:177** — The subscriber's signing secret is written to the debug log in plaintext. Remove the secret from the log statement entirely; logging the endpoint alone is sufficient.
- **src/notify/webhook.js:181** — Retries fire back-to-back with no delay, so a struggling receiver gets three immediate hits. Add a backoff (e.g. exponential with jitter) between attempts.
- **src/notify/webhook.js:168** — Destroying the request on timeout emits an `error` that rejects `postOnce`, but the retry loop then reuses the same `options` object across attempts; confirm the stale `timeout` and header state do not leak between requests, and construct fresh options per attempt.

## Suggestions

- **src/notify/webhook.js:143** — `new URL(endpoint)` throws synchronously on a malformed endpoint, so `deliver` rejects with an opaque `TypeError`. Validate the endpoint and reject with a domain-specific error naming the subscriber.
- **src/notify/webhook.js:146** — The protocol is taken from the parsed URL, so an `http:` endpoint is passed to `https.request` and fails obscurely. Reject non-HTTPS endpoints explicitly.
- No tests accompany this behaviour. Add a unit test for `deliver` covering the retry path: a 500 followed by a 200 should return 200 after two attempts, and three consecutive 500s should throw.
