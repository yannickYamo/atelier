## Summary

This change adds retry helpers for the sync subsystem: an exponential-backoff calculator with optional jitter, a `call_with_retry` wrapper that retries on `TransientError`, and two convenience helpers for draining a queue and waiting on endpoint readiness. The backoff is capped at `MAX_BACKOFF` and the final error is re-raised once attempts are exhausted.

## Must fix

- **src/sync/retry.py:142** — `wait_until_ready` spins on `probe()` with no sleep and no attempt limit. When `deadline` is `None` this is an unbounded busy-wait that will peg a CPU core; add a sleep between probes and require or default a deadline.
- **src/sync/retry.py:126** — If `attempts` is `0` or negative the loop body never runs and `last_error` is `None`, so `raise last_error` fails with `TypeError: exceptions must derive from BaseException`. Validate `attempts >= 1` up front.
- **src/sync/retry.py:134** — `drain_queue` pops the item before calling the handler, so an item whose retries are exhausted is lost and the raised error leaves `processed` discarded. Re-queue or report failed items rather than dropping them.

## Suggestions

- `compute_backoff` adds jitter after the `MAX_BACKOFF` clamp (line 111), so the returned delay can exceed the documented maximum; clamp after applying jitter.
- `drain_queue` uses `queue.pop(0)`, which is O(n) on a list; `collections.deque.popleft` would be cheaper for large queues.
- No tests accompany this change. Add unit tests for `call_with_retry` covering success on a later attempt, exhaustion re-raising the last error, and for `wait_until_ready` hitting its deadline.
